# Research finding evidence acceptance

The exporter verifies consistency of stored C0 evidence. It does not rerun an experiment or
establish the authenticity or empirical validity of a study.

## Source decisions and public gates are different contracts

WB-C1's source acceptance rule requires a positive baseline false-alert rate and a candidate
rate no greater than 80 percent of it. The public projection's improvement gate means only
strictly lower. A source decision is checked using the former rule; neither rule replaces the
other. All other carried source gate measurements, explicit selection viability, and recorded
reason order are checked before copying a decision.

A bundle without a stored MethodTrialView lacks threshold-selection evidence. It cannot prove
`benchmarked`. A `reject` can be transported only when all its recorded reasons equal the
failed rules established by its carried measurements. Missing selection, delay and confound
measurements remain unavailable; missing gate inputs never become fabricated zeroes or false
claims. A rejection based on an uncarried selection reason is refused as insufficient evidence.

WB-C1 has no registered `revise_once` evidence recipe. The transport schema retains that enum,
but this adapter refuses it rather than inventing a revision decision. Future non-reject source
formats need a separately reviewed evidence adapter; the current pinned MethodTrialView is a
rejection-only exhibit. Issue #97 remains open for any broader outcome support, the explicit
post-write privacy acceptance item, and paired Product-side verification.

## View and receipt linkage

Before supplemental view measurements can be used, the view's ResearchPack producer commit
must match the verified input snapshot. Its custody digest must select a JSON reference in the
same EvaluationBundle's artifact manifest. During stored export, that reference must equal the
run manifest's custody reference, and its actual bytes must satisfy size and digest checks.
The existing receipt's event, run, generator, dataset checksum, parameter checksums, digest
shapes and finite nonnegative thresholds are checked. Only the receipt is read; no held-out
observations are accessed and no custody event is created.

The test fixture uses a new invented receipt and explicitly rehashes its linked bundle and
view. The historical release assets remain unchanged. Its public projection still must match
the exact Product golden finding file.
