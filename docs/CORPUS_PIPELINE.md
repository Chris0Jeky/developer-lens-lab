# Corpus pipeline

Network collection is disabled during bootstrap.

A future authorized pipeline proceeds from one candidate question and deterministic baseline to a
frozen sampler, bounded public-metadata request, in-memory projection, coverage/quality profile,
ResearchPack, leakage-aware features, repository/time splits, baseline comparison, EvaluationBundle,
and reject/revise/benchmarked decision.

Constitution v2 permits raw source content and modular read capabilities once the relevant lane is
mechanically active; that charter-level permission does not widen the initial pilot. The pilot uses
an untracked allowlist and task-local opaque repository scopes, parses bounded REST responses in
memory, projects only its declared schema, discards raw bytes, and uses no token unless the exact
approved scope supplies one. Its default capability profile is Actions, Deployments, and Source
Structure. Dependencies, security aggregates, Discussions, text, diffs, logs, and artifacts are
modular opt-ins and never silently activate. Request, page, time, storage, retention, and deletion
budgets are fixed before collection; secrets remain prohibited absolutely, collected content is
never executed, and truncation, permission, rate limit, and absence remain coverage.

Expansion beyond an initial bounded pilot requires a passed deletion/coverage/balance report and a
named candidate sample/power need. Data availability never defines the product question.
