# Named home-directory manifest paths — issue #107

The manifest guard now rejects `~name/` and `~name\\` prefixes as well as the previously rejected
`~/` form. A leading named-home path must not become portable manifest content merely because it
does not begin with a drive, slash, or traversal segment. Bare/embedded tildes and ordinary relative
names retain their previous behavior. The rejection is the fixed `manifest contains a local path`
diagnostic and does not expose the supplied path.

Eight regressions failed before the fix; the complete focused validation selection passed 61
afterward. Coverage includes direct values, nested mappings/lists, whitespace, both separators,
invented names, and similar allowed text. Changed-file Ruff, strict Pyright, and whitespace checks
passed. Integrated/hosted proof belongs in the delivering PR. Reverting the small guard/test commit
restores the previous behavior; no schema or artifact bytes changed.
